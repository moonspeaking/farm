# «Ферма Айрис» (Magic Farm 1) → PWA (TypeScript + PixiJS)

Личный порт первой «Волшебной фермы» (в русской версии «Ферма Айрис», SmallGames). Графика,
тексты и правила берутся из установленной игры, код написан заново. Ресурсы принадлежат
правообладателю: сборка только для себя, в магазины не выкладывать.

Вторая часть портируется рядом, в `~/PycharmProjects/MagicFarm2Port`. Там ресурсы упакованы
в `main.pak`, а анимации лежат в 3D-формате `.a3d`. В первой части всё проще: обычные картинки
PopCap (`X.jpg` — цвет, `X_.png` — альфа в яркости), а правила лежат в XML без архива.

## Ресурсы

```bash
GAME="$HOME/Library/Application Support/CrossOver/Bottles/Farm/drive_c/Program Files/Game0"
python3 tools/export_mf1.py "$GAME" web     # нужен Pillow
```

Скрипт кладёт картинки в `web/public/img/*.webp` (с альфой), а правила и русские тексты — в `web/public/data/rules.json`.
Источники в игре:
- `xml/properties_ru.xml` — растения, продукты, стартовые значения (`common`), грядки первой локации;
- `xml/locations/location_1.xml` — длина дня, колодец, бочки и ящики по уровням, набор семян;
- `xml/locations/items.xml` — цены грядки, воды и колодца;
- `xml/ru/ru.xml` — все надписи (в cp1251 без объявления кодировки).

## Экраны

Кнопки только из оригинала: круглые `buttons/back`, кнопки магазина `shop_button_small/medium` на объектах,
текстовые кнопки без подложки в цветах `button_styles` (`normal` — «Да», «Нет», «OK», «Назад»;
`shop` — «Один», «Все»; `menu` — пункты главного меню).

**Игроки** (`select_user`, `new_user`): как в оригинале, можно завести несколько учётных записей. При первом запуске игра спрашивает имя («Введите ваше имя.»), вверху главного меню — «Приветствую, %name%, если это не Вы, нажмите сюда», по нажатию — список игроков («Создать», «Удалить», OK). У каждого игрока своё сохранение и свои подсказки (`localStorage`: `iris-farm-profiles`, `iris-farm-save-v3:<id>`), рекорды и опции общие; в рекорды пишется имя игрока. Сохранение, сделанное до появления игроков, достаётся первому созданному.

**Главное меню** (`main_menu`): «Кампания», «Опции», «Результаты», «Выйти» на табличке, жёлтым цветом
стиля `menu`. «Кампания» спрашивает «Продолжить игру или начать новую?», если есть сохранение.
Новая игра начинается со вступительного комикса (`first_comics`) и попадает в город к слуге.
Опции, результаты и выход пока заглушки.

**Город** (`town_screen`, фон `game/towns/location_1`): персонажи стоят по позициям `quest_holders`,
над тем, у кого есть задание, висит значок. Персонаж появляется, когда у него есть задание (сыщик
«приезжает» на следующий день); слуга Мистер Гардинер виден всегда. Сверху, как на ферме, две круглые
кнопки оригинала: «На Карту» (`to_global_map`, карта пока не перенесена) и «На Ферму» (`shop_screen_farm`).

**Разговоры** (`quest_dialog`): свиток, портрет говорящего (`talkers/*`), имя, реплика,
стрелки «назад/дальше», варианты ответа. Недоступные ответы скрыты.

**Квесты** берутся из `xml/locations/location_1_quests.xml`, тексты — из `ru.xml`
(`quests/location_1/quests/...`): реплики сопоставляются по порядку, `phrase_N` ↔ N-я реплика,
`answer_N` ↔ N-й ответ. Движок (`web/src/quests.ts`) выполняет:
- условия `have_mark`, `have_items` (деньги, плоды со склада, предметы квестов), `quest_status`, `day_delay`;
- действия `enable_sub_quest` / `disable_sub_quest`, `set_quest_status`, `set_mark`, `add_items`, `remove_items`,
  `set_money`, `enable_buy_vegetation` / `disable_buy_vegetation`, `remove_all_vegetations`.
Действия про другие города, фермы, помощника, вредителей и букеты пока только запоминаются
(эти части не перенесены). Поэтому сюжет проходится, пока не потребуются карта мира или предметы
от вредителей. Например, начало: слуга просит 50 монет на сыщика → сыщик приезжает на следующий день и просит
400 монет на дорогу в порт.

## Игра на ферме

```bash
cd web
npm install
npm run dev            # http://localhost:5173, ?speed=10 ускоряет игровые таймеры
```

Экран 800×600, как в оригинале, вписывается в окно с полями. Слева панель статистики Айрис
(склад, вода, деньги, день, «Меню»), сверху справа часы дня.

**Подготовка к дню.** Магазин работает прямо на объектах фермы (`shop_control/click_obj_buttons`):
- пустая грядка: «Посадить растение» открывает свиток с набором `buy_vegetation_set` — Ромашка 20$, Денежное дерево 40$, Роза 80$;
- грядка с растением: «Продать <растение>» за `price_sell` с подтверждением;
- свободное место: «Купить грядку 50$» (4 места `not_installed`), с подтверждением оригинала;
- бочки: «Купить бочку» (75$, 250$) и «Купить воду» — долить бочки по 2$ за литр;
- ящики: «Купить ящик» (100$, 300$) и «Продать плоды» — экран продажи с кнопками «Один» и «Все»;
- круглая кнопка «Начать День» (позиция `start_day`: 527; −110). Перед стартом — предупреждения оригинала
  («Мало воды. Все равно начать день?»).

**День** длится `time` = 40 с из `location_1.xml`. Растения хотят пить через `hunger_min…hunger_max`,
над ними появляется капля, полив стоит 1 литр. Политое растение растит плоды за `min…max_product_delay`
в узлах `nodes`, продукт выбирается по `probability`. Плоды собираются на склад, пока на нём есть место.
Колодец даёт ведро воды. Прогресс сохраняется в `localStorage`, «Меню» начинает новую игру.

**Вредители** (`bugs`, `location_1/bug_arriver`). Каждый день идёт своя волна из 15 (дальше повторяется последняя).
Группы вредителей выходят по очереди: `delay` — пауза после группы. Вредители появляются у краёв фермы
(`arrive_positions`) и ползут к ближайшему растению. Там они едят его: `attack` единиц жизни за каждый проход анимации `eat`.
Съеденное растение исчезает. Улитка (`snail`, 8 жизней), хитрая улитка в панцире (`snail_2` → после
разбитого панциря `snail_no_armour`, 3 жизни, вдвое быстрее) и оса (`pchela`, 4 жизни, быстрая).
Нажатие по вредителю бьёт его мечом (`simple_sword attack` = 1). Анимации `move / eat / hit / stand / reincorn`
нарезаются из вертикальных полос оригинала в 5 направлениях, влево — зеркально. Предметы (`items`, например
`snail_shell` для квеста странника) выпадают, только пока квест разрешил это действием `enable_bug_item`.
К концу дня вредители уходят.

**Робин** (`common/helper`) появляется после разговора со слугой (квест `helper`, действие `enable_helper`).
Он летит к ближайшему вредителю со скоростью `speed` = 100 и бьёт его на `attack` = 1 раз в `attack_period` = 0,5 с
с расстояния до `attack_range` = 75. Если вредителей нет, каждую секунду с вероятностью `start_skill_prob` = 0,3
он поливает жаждущее растение (тратит воду из бочек) или собирает созревший плод. Над Робином видна иконка
текущего дела (`attack_icon` / `pour_icon` / `product_icon`). Между днями он отдыхает у дома.

**Старт:** 30$, 7 л воды, ромашка уже растёт (`vegetations_at_start`), 6 грядок, по одной бочке и одному ящику (у первого уровня цена 0).

Допущения (в XML этого нет или смысл поля не ясен):
- `capacity` уровня бочек и ящиков — общая вместимость после покупки уровня (8 → 10 → 12 л, 15 → 20 → 25 плодов);
- `upgrade` растения — сколько плодов собрать, чтобы оно перешло на следующую стадию (ромашка → ромашка 2 → ромашка 3);
- колодец: ведро на `water_capacity` = 5 л поднимается `fill_time` = 1 с, следующее — через `delay` = 20 с;
- растение без воды теряет 1 единицу `life` каждые 5 с и засыхает на нуле;
- волна вредителей = номер дня, атрибут `delay` у самой волны не используется (его смысл не ясен);
- Робин выбирает себе дело с вероятностью `start_skill_prob`; рост умений (`per_level_skill_prob`) не перенесён;
- погода (`whether`), опыт и умения, карта мира, другие города и букеты пока не перенесены.

## Память и загрузка

Картинки делятся на общие (`core_images`, ≈22 МБ в распакованном виде, грузятся при запуске) и по локациям (`location_images`: вредители, фоны, ящики, портреты). Картинки локации подгружаются при первом входе в неё (с надписью «Идет загрузка...»), так в памяти нет неиспользуемых локаций: на запуске ≈40 МБ распакованных картинок вместо ≈85 МБ. Разбиение считает `tools/export_mf1.py` (`split_images`).

## Запуск и установка (PWA)

- Разработка: `cd web && npm run dev`; сборка: `npm run build` (в `web/dist` ложатся и `sw.js` со списком файлов для офлайна).
- Публикация: GitHub Pages через `.github/workflows/pages.yml` (при пуше в `main`). Пути в сборке относительные, подпапка репозитория не мешает.
- Установка на телефон: открыть страницу в Chrome → меню → «Установить приложение» / «Добавить на главный экран». Запускается на весь экран без рамок браузера (`display: fullscreen`) в альбомной ориентации, после первой загрузки работает без сети. В браузере клавиша F включает и выключает полный экран.
- Профиль (прогресс, настройки, рекорды) хранится в `localStorage` браузера на устройстве; при установке приложения запрашивается постоянное хранилище, чтобы его не вычищали.

## Первая локация: что реализовано

- Левая панель Айрис (опыт, склад, вода, деньги, день) растровыми шрифтами оригинала (`tools/export_fonts.py`).
- Рост уровня и умения (skills.xml), окно «Поднять уровень».
- Цветочный магазин: корзина с цветами, перетаскивание цветов в 4 заказа-букета, оплата за готовый букет; продажа «Один/Все».
- Звук и музыка (`audio.ts`), меню игры, опции, таблица рекордов, пауза по пробелу.
- Не перенесено: частицы `.psi`, бонусные события, особые курсоры, другие локации.

## Частицы, ведро, туториал

- `.psi` (`data/particles`) разобран полностью по дизассемблеру exe: раскладка 128 байт описана в `tools/export_particles.py`, эмиттер воспроизведён в `web/src/particles.ts` (шаг симуляции 1/60 с, как покадровое обновление игры). Звёздочки `*-changes` вылетают из счётчиков панели, `level-available` — бесконечный эмиттер над полоской опыта при свободных очках умений. Не определено по коду: режим наложения (взят аддитивный) и точки эмиттеров (по счётчикам панели).
- Ведро у колодца поднимается и наклоняется за `fill_time` (анимация моя, в данных её нет).
- Туториал: затемнение `fader_alpha` с «окном» под светлой картинкой и позиции пузырей берутся из `properties_ru.xml → tutorial` (`tutorial_steps` в rules.json).
